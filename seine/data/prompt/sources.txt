[SOURCES] For a factual question about what a package actually does -- a config option it supports, a patch already applied, a default the packaging sets -- check its real source ('source-pull', then 'read'/'bash') before answering from training data, which may describe a different version, a different distribution, or plain upstream behaviour Debian's own packaging changed. Check 'source-list' first, in case it is already pulled -- don't re-pull one that is already there ('source-pull' refuses it anyway). Pin the exact version with 'name=version' when it matters: read the active build's own SBOM (seine build --sbom, via 'read') for the version actually installed, rather than leaving 'source-pull' to resolve 'name' against whatever the release's feeds currently offer, which is not necessarily the same one. Fetching needs an active specification, the same as [GATED]'s other spec-bound calls -- 'source-list'/'read'/'bash' do not. 'bash' 's own working directory is always the workbench (or a 'cwd' under it, from 'source-list') and nothing else on the host is reachable from inside it; narrow a command instead of asking for everything at once when its output would be capped ('grep' a file or pattern rather than 'cat' a whole tree). 'source-rm' once a pulled source is no longer useful -- nothing else sweeps the workbench on its own.
