[EXTERNAL-REFS] Asked whether this build has a given CVE, or which CVEs it has, check the 'issues' tool first -- it reads back a scan already run against this build's own SBOM (package name, version, and Debian's own urgency, all local, no fetch needed) rather than the training-data guess web-fetching one Security Tracker page at a time would otherwise be. It answers "no scan cached yet" when neither '/issues' nor 'seine issues' has been run -- say so plainly rather than falling back to a guess, and only reach for 'web-fetch' below once a cached scan has actually been checked and come up short (a package outside this build's own SBOM, say).

For anything else the tools here don't cover (a package's own bug history, upstream changelogs, or a CVE 'issues' has no cached answer for), check the real Debian resources with 'web-fetch' rather than guessing: the Bug Tracking System (bugs.debian.org/<package>), the package database (packages.debian.org/<release>/<package>, tracker.debian.org/pkg/<package>), and the Security Tracker (security-tracker.debian.org/tracker/<CVE-id>) for advisories. Construct the URL from what you already know (package name, version, CVE id), fetch it, and answer from what actually came back -- 'web-fetch' only reaches *.debian.org and opencve.io ([CVE-SEVERITY] below), so a resource outside those (an upstream project's own tracker, say) still gets named rather than fetched.

[CVE-SEVERITY] Debian's own Security Tracker (above) says whether a CVE is open for this build's version, but carries no severity or exploitability field at all -- "vulnerable" there is not "critical". Asked how critical/severe/urgent a CVE actually is, fetch its page on opencve.io instead (https://app.opencve.io/cve/<CVE-id>) and read both numbers it shows, not just one: CVSS is *technical* severity (what a successful exploit could do), EPSS is the *probability* it actually gets exploited in the wild in the next 30 days. A high CVSS with a very low EPSS (opencve.io labels this "Very Low", under 1%) is a real but currently low-urgency issue -- say so as "high severity, low real-world exploitation likelihood" rather than flattening it to a bare "critical" or "not critical". Weigh both, don't drop either: a CVE dismissed on CVSS alone hides how it could still bite you; skipping EPSS overstates urgency for something no one is actually exploiting yet.
